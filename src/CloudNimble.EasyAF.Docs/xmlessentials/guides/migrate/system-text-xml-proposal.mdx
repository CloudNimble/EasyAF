This article compares XmlEssentials with the `System.Text.Xml` API proposed in [dotnet/runtime issue 125299](https://github.com/dotnet/runtime/issues/125299). It goes through the proposal section by section and gives, for each proposed type and member, the XmlEssentials name and a status. It's for readers who know the proposal and want to see how much of it this library implements, and where it differs.

The comparison is against the proposal text as of November 2026 and the current XmlEssentials source. Each row was checked against the source.

## How to read the tables

The proposal puts its types in `System.Text.Xml` and `System.Text.Xml.Serialization`. XmlEssentials uses `CloudNimble.Text.Xml`, `CloudNimble.Text.Xml.Serialization`, and `CloudNimble.Text.Xml.Nodes`.

The proposal names its types with `XmlData` (`XmlDataSerializer`, `Utf8XmlDataReader`, `XmlDataElementAttribute`) to keep them apart from the types in `System.Xml`. XmlEssentials uses the shorter names without `Data` (`XmlSerializer`, `Utf8XmlReader`, `XmlElementAttribute`), which follow the System.Text.Json names with `Json` replaced by `Xml`. Several of those names are also names in `System.Xml` and `System.Xml.Serialization`, so a file that imports both namespaces needs an alias.

| Status | Meaning |
| --- | --- |
| Same | The name and the signature match the proposal. |
| Renamed | The signature matches. Only the name differs, in the way the previous paragraph describes. |
| Different shape | The capability exists with a different signature, type, or default. The row says how. |
| Partial | Some of the proposed overloads exist. The row says which. |
| Not implemented | XmlEssentials has no counterpart. |
| Added | XmlEssentials has a member that the proposal doesn't list. |

## Summary

| Proposal section | Result |
| --- | --- |
| Enums | `XmlTokenType` is the same. `XmlCommentHandling` has the same members with different values. |
| Reader options and state | Renamed. Every proposed member exists. The default comment handling differs. |
| Reader | Renamed. Every proposed member exists. The constructors have a different shape. |
| Writer options | Renamed. Every proposed member exists. |
| Writer | Renamed. Every proposed method group exists. One group, `WriteAttributeString`, has one overload fewer than proposed. |
| Mapping attributes | Seven of twelve are renamed. Three have a different shape. Two are not implemented. |
| Serializer options | Renamed. Every proposed member exists. `TypeInfoResolver` has a different type. |
| Serializer | Renamed. Every proposed overload exists. |
| Converters | Renamed. Every proposed member exists. |
| Source generation | Renamed. Every proposed member exists. |

## The proposal's usage examples

The following sections run the examples from the proposal's "API Usage" section with XmlEssentials. Each is a tested sample, and the output shown is the real output.

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/45_SystemTextXmlProposal.cs)

### Basic and span-based serialization

The proposal's `Person` is the `Contact` class here, with `[XmlRoot("Person")]`.

```csharp Program.cs
var person = new Contact { Name = "Alice", Age = 30 };

string xml = XmlSerializer.Serialize(person);
Contact? p = XmlSerializer.Deserialize<Contact>(xml);
output.WriteLine(xml);
output.WriteLine($"{p!.Name} is {p.Age}");

ReadOnlySpan<byte> utf8XmlSpan = "<Person><Name>Bob</Name></Person>"u8;
Contact? p2 = XmlSerializer.Deserialize<Contact>(utf8XmlSpan);
output.WriteLine($"{p2!.Name} is {p2.Age}");

ReadOnlySpan<char> xmlSpan = "<Person><Name>Alice</Name><Age>30</Age></Person>".AsSpan();
Contact? p3 = XmlSerializer.Deserialize<Contact>(xmlSpan);
output.WriteLine($"{p3!.Name} is {p3.Age}");
```

The code produces the following output:

```text
<?xml version="1.0" encoding="utf-8"?><Person><Age>30</Age><Name>Alice</Name></Person>
Alice is 30
Bob is 0
Alice is 30
```

`Age` comes before `Name` because `Contact` declares it first.

### A reader over a sequence

```csharp Program.cs
var utf8XmlSequence = new ReadOnlySequence<byte>("<Person><Name>Carol</Name><Age>41</Age></Person>"u8.ToArray());

var reader = new Utf8XmlReader(utf8XmlSequence);
Contact? person = XmlSerializer.Deserialize<Contact>(ref reader);

output.WriteLine($"{person!.Name} is {person.Age}");
```

The code produces the following output:

```text
Carol is 41
```

### Partial reads with reader state

The proposal's loop reads each chunk with a new reader. This version also carries over the bytes that the previous reader didn't consume, which the proposal's loop leaves out.

```csharp Program.cs
byte[] xml = """<Order id="1042"><Item>Keyboard</Item><Item>Mouse</Item></Order>"""u8.ToArray();

var state = new XmlReaderState(new XmlReaderOptions { MaxDepth = 64 });
int start = 0;
int end = 0;

while (end < xml.Length)
{
    end = Math.Min(end + 24, xml.Length);
    bool isFinal = end == xml.Length;

    var reader = new Utf8XmlReader(xml.AsSpan(start, end - start), isFinalBlock: isFinal, state);
    while (reader.Read())
    {
        output.WriteLine($"Token: {reader.TokenType}, Depth: {reader.CurrentDepth}, Consumed: {reader.BytesConsumed}");
    }

    start += (int)reader.BytesConsumed;
    state = reader.CurrentState;
}
```

The code produces the following output:

```text
Token: StartElement, Depth: 0, Consumed: 17
Token: StartElement, Depth: 1, Consumed: 23
Token: Text, Depth: 2, Consumed: 8
Token: EndElement, Depth: 1, Consumed: 15
Token: StartElement, Depth: 1, Consumed: 21
Token: Text, Depth: 2, Consumed: 5
Token: EndElement, Depth: 1, Consumed: 12
Token: EndElement, Depth: 0, Consumed: 20
```

`BytesConsumed` counts from the start of the current buffer, as it does in `Utf8JsonReader`.

### Namespace-aware mapping

The proposal's example uses `XmlDataNamespaceDeclaration` to choose the prefix `addr`, and `XmlDataType` to put the members of `Address` in a namespace. `XmlDataType` has no counterpart, so this mapping names the namespace on each member, and it leaves the prefix to the writer:

```csharp Employee.cs
[XmlRoot("Person", Namespace = "http://example.com/person")]
public sealed class Employee
{
    [XmlAttribute("age")]
    public int Age { get; set; }

    [XmlElement("Address", "http://example.com/address")]
    public Address? HomeAddress { get; set; }

    [XmlElement("FullName")]
    public string? Name { get; set; }
}

public sealed class Address
{
    [XmlElement(Namespace = "http://example.com/address")]
    public string? City { get; set; }

    [XmlElement(Namespace = "http://example.com/address")]
    public string? Country { get; set; }
}
```

```csharp Program.cs
var person = new Employee
{
    Name = "Alice",
    Age = 30,
    HomeAddress = new Address { City = "Seattle", Country = "US" },
};

var options = new XmlSerializerOptions { WriteIndented = true, NewLine = "\n", OmitXmlDeclaration = true };
output.WriteLine(XmlSerializer.Serialize(person, options));
```

The code produces the following output:

```xml
<Person xmlns="http://example.com/person" age="30">
  <Address xmlns="http://example.com/address">
    <City>Seattle</City>
    <Country>US</Country>
  </Address>
  <FullName>Alice</FullName>
</Person>
```

Every element has the same namespace as in the proposal's expected output. The spelling is different: the address namespace is the default namespace of the `Address` element, where the proposal's output declares the prefix `addr` on the root. To declare that prefix on the document element, add `[XmlNamespaceDeclaration("addr", "http://example.com/address")]` to `Employee`. `Address` comes before `FullName` because the class declares `HomeAddress` first.

### A reader with namespace comparison

```csharp Program.cs
ReadOnlySpan<byte> utf8Xml = """
    <root xmlns:ns="http://example.com">
      <ns:Child>value</ns:Child>
    </root>
    """u8;

var reader = new Utf8XmlReader(utf8Xml);
while (reader.Read())
{
    if (reader.TokenType == XmlTokenType.StartElement)
    {
        if (reader.LocalNameEquals("Child"u8) &&
            reader.NamespaceUriEquals("http://example.com"u8))
        {
            reader.Read();
            string? value = reader.GetString();
            output.WriteLine(value);
        }
    }
}
```

The code produces the following output:

```text
value
```

Apart from the type name, this is the proposal's code.

### A writer with namespaces

```csharp Program.cs
using var stream = new MemoryStream();

using (var writer = new Utf8XmlWriter(stream, new XmlWriterOptions { Indented = true, NewLine = "\n" }))
{
    writer.WriteXmlDeclaration();
    writer.WriteStartElement("root");
    writer.WriteNamespaceDeclaration("ns", "http://example.com");
    writer.WriteDefaultNamespace("http://example.com/default");

    writer.WriteStartElement("ns", "Child", "http://example.com");
    writer.WriteAttributeString("ns", "id", "http://example.com", "42");
    writer.WriteStringValue("Hello");
    writer.WriteEndElement();

    writer.WriteEndElement();
    writer.Flush();
}

output.WriteLine(Encoding.UTF8.GetString(stream.ToArray()));
```

The code produces the following output:

```xml
<?xml version="1.0" encoding="utf-8"?>
<root xmlns:ns="http://example.com" xmlns="http://example.com/default">
  <ns:Child ns:id="42">Hello</ns:Child>
</root>
```

The method calls are the proposal's, and the XML is the proposal's expected output.

### Source generation

```csharp MigrationXmlContext.cs
[XmlSerializable<OrderLine>]
internal sealed partial class MigrationXmlContext : XmlSerializerContext
{
}
```

```csharp Program.cs
var line = new OrderLine { Sku = "KB-01", Description = "Keyboard" };

string xml = XmlSerializer.Serialize(line, MigrationXmlContext.Default.OrderLine);
OrderLine? copy = XmlSerializer.Deserialize(xml, MigrationXmlContext.Default.OrderLine);
output.WriteLine(xml);
output.WriteLine($"{copy!.Sku}: {copy.Description}");

ReadOnlySpan<byte> utf8 = Encoding.UTF8.GetBytes(xml);
OrderLine? copy2 = XmlSerializer.Deserialize(utf8, MigrationXmlContext.Default.OrderLine);
output.WriteLine($"{copy2!.Sku}: {copy2.Description}");
```

The code produces the following output:

```text
<?xml version="1.0" encoding="utf-8"?><OrderLine sku="KB-01">Keyboard</OrderLine>
KB-01: Keyboard
KB-01: Keyboard
```

`OrderLine` has an `[XmlAttribute("sku")]` member and an `[XmlText]` member. The context exposes `Default` and one `XmlTypeInfo<T>` property for each listed type, as the proposal's `AppXmlContext.Default.Person` does.
