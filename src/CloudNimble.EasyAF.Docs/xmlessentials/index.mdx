For the better part of a decade, .NET developers have asked for XML that works the way JSON does in System.Text.Json: one static call to serialize, a UTF-8 reader that doesn't allocate, a source generator, and Native AOT that works. **XmlEssentials is that library.** It's a complete XML stack written from scratch, with no dependency on `System.Xml`, and it's ready for production today.

### The System.Text.Json equivalent for XML that .NET developers have been begging for!

```csharp
using CloudNimble.Text.Xml;

var person = new Person { Name = "Ada", Age = 36 };

string xml = XmlSerializer.Serialize(person);
Person? copy = XmlSerializer.Deserialize<Person>(xml);
```

```xml
<?xml version="1.0" encoding="utf-8"?><Person><Name>Ada</Name><Age>36</Age></Person>
```

## Everything System.Text.Json taught you, now for XML

If you know System.Text.Json, you already know XmlEssentials. The types, the method names, and the patterns carry straight over.

| System.Text.Json | XmlEssentials | What it does |
| --- | --- | --- |
| `JsonSerializer` | [`XmlSerializer`](/xmlessentials/guides/serialize) | Turns objects into XML and back with one static call |
| `Utf8JsonReader` | [`Utf8XmlReader`](/xmlessentials/guides/use-utf8xmlreader) | Reads UTF-8 one token at a time, without allocating |
| `Utf8JsonWriter` | [`Utf8XmlWriter`](/xmlessentials/guides/use-utf8xmlwriter) | Writes UTF-8 straight into your buffer or stream |
| `JsonDocument` | [`XmlDocument`](/xmlessentials/guides/use-xmldocument) | A read-only, pooled document you can query |
| `JsonNode` | [`XmlNode`](/xmlessentials/guides/use-xmlnode) | A document you can build and change in memory |
| `JsonSerializerContext` | [`XmlSerializerContext`](/xmlessentials/guides/source-generation) | Source-generated serialization with no reflection |
| `JsonSerializerOptions` | [`XmlSerializerOptions`](/xmlessentials/guides/configure-options) | Naming policies, converters, and limits in one place |
| `JsonConverter<T>` | [`XmlConverter<T>`](/xmlessentials/guides/custom-converters) | Your own reading and writing for any type |

Coming from JSON? [Start with what's different about XML](/xmlessentials/guides/migrate/from-system-text-json).

## Lightning fast, and light on memory

XmlEssentials reads and writes UTF-8 directly. There's no transcoding to UTF-16, no string for every name, and no object for every node. Across 67 like-for-like benchmarks against `System.Xml`, it's 3.0× faster on average and allocates 85% less memory.

## How it compares

| | System.Xml | System.Text.Json | XmlEssentials |
| --- | --- | --- | --- |
| Format | XML | JSON | XML |
| One-call static serializer | No | Yes | Yes |
| UTF-8 span reader and `IBufferWriter<byte>` writer | No | Yes | Yes |
| Read-only DOM in pooled memory | No | Yes | Yes |
| DOM you can edit | Yes | Yes | Yes |
| Roslyn source generator | No | Yes | Yes |
| Native AOT serialization | No | Yes | Yes |
| Positional records and constructor parameters | No | Yes | Yes |
| Non-public types | No | Yes | Yes |
| Dictionaries | No | Yes | Yes |
| `IAsyncEnumerable<T>` streaming | No | Yes | Yes |
| XML 1.1 | No | | Yes |
| DTD processing and XSLT | Yes | | No |

XmlEssentials is deliberately not a drop-in copy of `System.Xml`. It leaves out DTDs, XPath, XSLT, and encodings other than UTF-8. If you need those, keep `System.Xml` for that part of your app. See [XML conformance](/xmlessentials/guides/xml-conformance) for the exact boundary.

## Tested like a platform library

- **100% line coverage and 100% branch coverage**, enforced on every build.
- **Thousands of tests**, run on both .NET 10 and .NET 11.
- **283 cases from the W3C XML Conformance Test Suite**, plus real documents from other parsers' test suites.
- **Documents are read split at every byte offset**, so XML that arrives in pieces reads the same as XML that arrives whole.
- **Every sample in these docs is compiled and tested.** If the docs show output, a test asserts it.
