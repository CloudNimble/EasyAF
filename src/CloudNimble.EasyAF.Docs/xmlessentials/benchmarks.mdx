XmlEssentials is faster than `System.Xml` in 66 of the 67 like-for-like comparisons on this page, by 3.0× on average, and it allocates 85% less memory on average. This page shows every number, explains what each one measures, names the comparison `System.Xml` wins, and tells you where XmlEssentials stands against System.Text.Json.

## How to read these tables

Each table compares the same work done by two or three libraries.

- **Time** is the mean time for one operation. A microsecond (µs) is 1,000 nanoseconds (ns).
- **Allocated** is the managed memory one operation allocates. Less memory means fewer garbage collections under load.
- **Faster** is the `System.Xml` time divided by the XmlEssentials time. "2.4×" means XmlEssentials does the work in well under half the time. It's computed from the measured times, before they're rounded for the table.
- **Less memory** is how much less XmlEssentials allocates than `System.Xml` for the same operation. "100%" means XmlEssentials allocates nothing. The cell is empty where `System.Xml` allocates nothing either, and "more" marks the two rows where XmlEssentials allocates more.

`System.Xml` is the baseline: `XmlReader`, `XmlWriter`, `XmlDocument`, `XDocument`, and a cached `System.Xml.Serialization.XmlSerializer`. System.Text.Json appears beside it as a yardstick for what a modern .NET serializer achieves. It reads and writes JSON, not XML, so it isn't doing the same job.

## Read real documents

The reader walks every token of four real files and keeps whitespace and comments. These files come from other parsers' test suites, and none of them was written for this library.

| Document | System.Xml | XmlEssentials | Faster | Less memory |
| --- | --- | --- | --- | --- |
| Word document (WordprocessingML, 11 KB) | 19.7 µs / 25,144 B | 12.9 µs / 944 B | 1.5× | 96% |
| RPM package metadata (21 KB) | 31.3 µs / 20,064 B | 15.3 µs / 80 B | 2.0× | 99.6% |
| OpenDocument text (57 KB) | 79.8 µs / 56,017 B | 43.9 µs / 6,952 B | 1.8× | 88% |
| RSS feed (198 KB) | 191.9 µs / 47,137 B | 82.4 µs / 1,441 B | 2.3× | 97% |

The few bytes XmlEssentials allocates are per reader, not per token: buffers for decoded values and for documents with more than eight attributes or namespaces on one element. Pass the reader a scratch buffer and all four files read with **0 bytes** allocated, in the same time:

| Document | XmlEssentials |
| --- | --- |
| Word document, scratch buffer | 12.8 µs / 0 B |
| RPM package metadata, scratch buffer | 15.2 µs / 0 B |
| OpenDocument text, scratch buffer | 43.3 µs / 0 B |
| RSS feed, scratch buffer | 83.0 µs / 0 B |

See [Use Utf8XmlReader](/xmlessentials/guides/use-utf8xmlreader#read-without-allocating).

## How XmlEssentials compares with System.Xml

The headline numbers come from every row above that has a `System.Xml` figure for the same work: 67 comparisons.

- **Speed.** XmlEssentials is faster in 66 of them. The average is 3.0×, which is the geometric mean of the Faster column, the right kind of average for ratios. The median is 2.3×. The smallest win is 1.1× and the largest is 19×.
- **Memory.** In the 66 comparisons where `System.Xml` allocates anything, XmlEssentials allocates 85% less on average, which is the mean of the Less memory column over those rows. In 32 of the 67 it allocates 0 bytes. It allocates more in two: the rows that change a tree.
- **By kind of work.** Single values are 4.3× to 19× faster, parsing real documents into a DOM is 3.1× to 3.4×, objects are 1.8× to 5.9×, reading real documents is 1.5× to 2.3×, and writing a DOM back out is 1.4× to 1.7×.

What's counted, so that you can check it:

- The tree rows count twice, once against `XmlDocument` and once against `XDocument`.
- The raw XML rows and the stream rows aren't counted, because `System.Xml` isn't doing the same work in them.
- Rows that have no `System.Xml` figure aren't counted.

## How XmlEssentials compares with System.Text.Json

XmlEssentials has the same API shape as System.Text.Json, so it's fair to ask whether it has the same speed. For objects, it does. For single values and the mutable tree, it doesn't. Of the 47 rows above that have a System.Text.Json figure:

- **Ahead in 10.** Objects of three derived types (read 100.4 µs against 142.6 µs, write 61.5 µs against 79.8 µs), a stream of 1,000 orders read (340.3 µs against 462.6 µs), and a long text value written in segments are the widest.
- **Level in 19.** The difference is inside the measurement error of the run. That covers most of the object rows: a customer, 1,000 orders, objects mapped as attributes, and objects with a decimal amount, read and written.
- **Behind in 18,** by 1.15× to 2.1×. The widest gaps are single values (56 ns against 27 ns to read an `int`), the mutable tree, a dictionary written, and checked raw XML.
- **Equal or lower in memory in 38 of the 47.**

XML asks more of a parser than JSON does. `<int>1</int>` is three tokens, and the name has to match at both ends; in JSON, `1` is one token. A whole XML document for one value also carries more bytes than the JSON for it. So a single XML value can't be read or written as fast as a JSON one. What you get instead is XML objects at the speed of JSON objects.

## How the benchmarks are run

- [BenchmarkDotNet](https://benchmarkdotnet.org) 0.15.8, `ShortRun` job with the in-process toolchain, .NET 11.0 on x64, Windows 11 on an Intel Core Ultra 9 285K (run under Hyper-V on 2026-11-25). Every table on this page comes from one run of the whole suite: 229 benchmarks.
- Each library reads the document it wrote itself, and each side keeps the same whitespace and comments.
- The `System.Xml` serializer and its reader and writer settings are created once and reused, which is the fastest way to use them. XmlEssentials writers are reused with `Reset`.
- The 0 B results are also enforced by unit tests that measure allocated bytes, so they can't drift without a test failing.
- The run uses the just-in-time compiler with its defaults. It doesn't measure a Native AOT build.
- Times move by 5% to 8% between runs on this machine. Compare the ratios, not the last digit.

    ```bash
    git clone https://github.com/CloudNimble/XmlEssentials.git

    ```
