## Summary

Defines the core behavior of policies that convert CLR type and member names to XML local names and provides a base for derived classes.

## Usage

`XmlNamingPolicy` converts .NET type and member names to XML names, so you can follow a naming convention without annotating every member. It is the counterpart of `JsonNamingPolicy`. Assign a policy to one of three properties of [`XmlSerializerOptions`](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlSerializerOptions):

| Property | Names it converts |
| --- | --- |
| `PropertyNamingPolicy` | Elements, XML attributes, and the document element, unless one of the next two is set. Also string dictionary keys, unless `DictionaryKeyPolicy` is set. |
| `ElementNamingPolicy` | Elements and the document element. |
| `AttributeNamingPolicy` | XML attributes. |

```csharp
var warehouse = new Warehouse { WarehouseCode = "SEA-2", StreetAddress = "400 Dock Rd", LoadingDocks = 12 };

var options = new XmlSerializerOptions
{
    OmitXmlDeclaration = true,
    PropertyNamingPolicy = XmlNamingPolicy.CamelCase,
};

string xml = XmlSerializer.Serialize(warehouse, options);
output.WriteLine(xml);

Warehouse? copy = XmlSerializer.Deserialize<Warehouse>(xml, options);
output.WriteLine($"{copy!.WarehouseCode}: {copy.LoadingDocks} docks");
```

The code produces the following output:

```text
<warehouse warehouseCode="SEA-2"><streetAddress>400 Dock Rd</streetAddress><loadingDocks>12</loadingDocks></warehouse>
SEA-2: 12 docks
```

A policy of `null`, the default, leaves names unchanged. The built-in policies are static properties: `CamelCase`, `PascalCase`, `SnakeCaseLower`, `SnakeCaseUpper`, `KebabCaseLower`, and `KebabCaseUpper`. To define your own, derive from `XmlNamingPolicy` and override `ConvertName`.

## Remarks

There is no identity policy. A [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null) policy on [XmlSerializerOptions](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlSerializerOptions) leaves
names unchanged, matching `System.Text.Json.JsonNamingPolicy`.

## Examples

The following examples show the built-in policies, separate policies for elements and attributes, and a policy of your own.

### The built-in policies

```csharp
const string name = "StreetAddress";

output.WriteLine($"CamelCase:      {XmlNamingPolicy.CamelCase.ConvertName(name)}");
output.WriteLine($"PascalCase:     {XmlNamingPolicy.PascalCase.ConvertName("streetAddress")}");
output.WriteLine($"SnakeCaseLower: {XmlNamingPolicy.SnakeCaseLower.ConvertName(name)}");
output.WriteLine($"SnakeCaseUpper: {XmlNamingPolicy.SnakeCaseUpper.ConvertName(name)}");
output.WriteLine($"KebabCaseLower: {XmlNamingPolicy.KebabCaseLower.ConvertName(name)}");
output.WriteLine($"KebabCaseUpper: {XmlNamingPolicy.KebabCaseUpper.ConvertName(name)}");
```

The code produces the following output:

```text
CamelCase:      streetAddress
PascalCase:     StreetAddress
SnakeCaseLower: street_address
SnakeCaseUpper: STREET_ADDRESS
KebabCaseLower: street-address
KebabCaseUpper: STREET-ADDRESS
```

### Different policies for elements and attributes

```csharp
var warehouse = new Warehouse { WarehouseCode = "SEA-2", StreetAddress = "400 Dock Rd", LoadingDocks = 12 };

var options = new XmlSerializerOptions
{
    OmitXmlDeclaration = true,
    ElementNamingPolicy = XmlNamingPolicy.KebabCaseLower,
    AttributeNamingPolicy = XmlNamingPolicy.SnakeCaseLower,
};

string xml = XmlSerializer.Serialize(warehouse, options);
output.WriteLine(xml);
```

The code produces the following output:

```xml
<warehouse warehouse_code="SEA-2"><street-address>400 Dock Rd</street-address><loading-docks>12</loading-docks></warehouse>
```

### A custom policy

```csharp
public sealed class LowerCaseNamingPolicy : XmlNamingPolicy
{
    public override string ConvertName(string name)
    {
        return name.ToLowerInvariant();
    }
}
```

```csharp
var warehouse = new Warehouse { WarehouseCode = "SEA-2", StreetAddress = "400 Dock Rd", LoadingDocks = 12 };

var options = new XmlSerializerOptions
{
    OmitXmlDeclaration = true,
    PropertyNamingPolicy = new LowerCaseNamingPolicy(),
};

string xml = XmlSerializer.Serialize(warehouse, options);
output.WriteLine(xml);
```

The code produces the following output:

```xml
<warehouse warehousecode="SEA-2"><streetaddress>400 Dock Rd</streetaddress><loadingdocks>12</loadingdocks></warehouse>
```

## Best Practices

- **Use the same options to read and to write.** The converted names are the ones the serializer looks for when it reads.
- **Prefer a policy to many attributes** when a whole format follows one convention, and use `[XmlPropertyName]` for the exceptions. A name set by an attribute isn't converted.
- **Make `ConvertName` deterministic.** The serializer calls it for the members of a type when it first uses the type and caches the result with the options, so a policy that returns different names over time gives inconsistent XML between options instances.
- **Return valid XML names** from a custom policy: no spaces, and no leading digit.
- **Don't apply a policy to dictionary keys unless the reader expects the converted keys.** The conversion happens when writing and can't be undone when reading.

## Considerations

- A policy converts type names as well as member names, so it changes the document element. With `CamelCase`, a type named `Warehouse` is written as `<warehouse>`.
- A policy doesn't convert names set with `[XmlRoot]`, `[XmlPropertyName]`, `[XmlElement]`, `[XmlAttribute]`, `[XmlArray]`, or `[XmlArrayItem]`, and it doesn't convert enumeration values.
- `CamelCase` and `PascalCase` change only the first character. `CamelCase` turns `XMLParser` into `xMLParser`. `JsonNamingPolicy.CamelCase` lowercases the whole leading run of capitals instead.
- The snake case and kebab case policies insert a separator before a capital that follows a lowercase letter, and before the last capital of a run that is followed by a lowercase letter. `XMLParser` becomes `xml_parser`. A digit doesn't start a new word.
- In a source-generated context, a policy is named with the [`XmlKnownNamingPolicy`](/xmlessentials/api-reference/CloudNimble/Text/Xml/Serialization/XmlKnownNamingPolicy) enumeration, because an attribute argument has to be a constant.
- The built-in policies are shared instances with no state.
