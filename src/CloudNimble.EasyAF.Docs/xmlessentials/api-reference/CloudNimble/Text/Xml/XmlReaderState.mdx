## Summary

Represents the state a [Utf8XmlReader](/xmlessentials/api-reference/CloudNimble/Text/Xml/Utf8XmlReader) needs to continue reading a document with more data.

## Usage

`XmlReaderState` is what lets a `Utf8XmlReader` read a document that arrives in blocks. A reader is a `ref struct` and can't outlive the block it reads, so everything it knows about the document so far travels in this value from one reader to the next. It's the counterpart of `JsonReaderState`.

You use it in two places:

1. Before the first block, create a state that holds your options:

   ```csharp
   var state = new XmlReaderState(new XmlReaderOptions());
   ```

2. For every block, pass the state to the reader's constructor, and take the new state from `CurrentState` when `Read` returns `false`:

   ```csharp
   var reader = new Utf8XmlReader(buffer.AsSpan(0, buffered), isFinalBlock, state);
   ```

   ```csharp
   state = reader.CurrentState;
   var consumed = (int)reader.BytesConsumed;
   ```

The state is opaque. Its only public member is `Options`, the options it was created with. The complete loop is in the examples.

## Remarks

The state is opaque. As with the state of a `Utf8JsonReader`, only [XmlReaderState.Options](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlReaderState#options) is
visible. [Utf8XmlReader.CurrentState](/xmlessentials/api-reference/CloudNimble/Text/Xml/Utf8XmlReader#currentstate) copies an immutable snapshot so two readers
never share mutable element or namespace stacks.

## Examples

The example is a sample in the repository whose output is checked by a test.

### Read a stream in blocks

The loop reads a block from a stream, gives it to a reader with the state of the previous reader, and keeps the bytes that the reader didn't consume for the next pass. The buffer is 16 bytes so that the sample has to refill it and grow it.

```csharp
using var stream = new MemoryStream(Encoding.UTF8.GetBytes(
    "<Orders><Order id=\"1042\"><Item>Keyboard</Item><Item>Mouse &amp; pad</Item></Order><Order id=\"1043\"><Item>Monitor stand</Item></Order></Orders>"));

// The buffer is small so that the sample has to refill it and grow it. Use 4096 bytes or more in an application.
var buffer = new byte[16];
var buffered = 0;
var isFinalBlock = false;
var state = new XmlReaderState(new XmlReaderOptions());

// What the application knows about its place in the document. The reader does not keep this between blocks.
var inItem = false;
var blocks = 0;

while (!isFinalBlock)
{
    var read = stream.Read(buffer, buffered, buffer.Length - buffered);
    buffered += read;
    isFinalBlock = read == 0;
    blocks++;

    var reader = new Utf8XmlReader(buffer.AsSpan(0, buffered), isFinalBlock, state);
    while (reader.Read())
    {
        switch (reader.TokenType)
        {
            case XmlTokenType.StartElement when reader.LocalNameEquals("Order"u8):
                while (reader.MoveToNextAttribute())
                {
                    if (reader.LocalNameEquals("id"u8))
                    {
                        output.WriteLine($"Order {reader.GetInt32()}");
                    }
                }

                break;

            case XmlTokenType.StartElement:
                inItem = reader.LocalNameEquals("Item"u8);
                break;

            case XmlTokenType.Text when inItem:
                output.WriteLine($"  Item: {reader.GetString()}");
                break;

            case XmlTokenType.EndElement:
                inItem = false;
                break;
        }
    }

    // Keep the bytes the reader did not consume. They are the start of a token that is not complete yet.
    state = reader.CurrentState;
    var consumed = (int)reader.BytesConsumed;
    buffer.AsSpan(consumed, buffered - consumed).CopyTo(buffer);
    buffered -= consumed;

    // A full buffer with nothing consumed means the next token is larger than the buffer.
    if (buffered == buffer.Length)
    {
        Array.Resize(ref buffer, buffer.Length * 2);
    }
}

output.WriteLine($"Read {stream.Length} bytes in {blocks} blocks. The buffer grew to {buffer.Length} bytes.");
```

```text
Order 1042
  Item: Keyboard
  Item: Mouse & pad
Order 1043
  Item: Monitor stand
Read 142 bytes in 8 blocks. The buffer grew to 32 bytes.
```

## Considerations

- **A state made without options uses the defaults.** `new XmlReaderState()` and `default(XmlReaderState)` hold the default options, with which the reader reports comments and white space between elements.
- **Taking a state allocates.** `Utf8XmlReader.CurrentState` copies the names of the open elements and the namespace bindings in scope, because the buffer they point into is about to be reused. The cost grows with the depth of the document and the number of namespaces in scope. `JsonReaderState` has no such cost. Take the state once per block, not once per token.
- **A state is a snapshot.** It never changes after you take it, and two readers created from the same state don't affect each other. You can keep a state and go back to it, as long as you still have the bytes that follow it.
- **A state doesn't hold bytes.** When `Read` returns `false` in the middle of a token, the reader stops at the start of that token. The bytes after `BytesConsumed` are yours to keep and pass again, followed by the new data.
- **A state holds what the next reader needs to read the same way.** That's the open elements and the namespaces in scope, the `xml:space` setting and whether each open element already has text (so white space is reported as it would be in one piece), the XML version, the line count, and the number of bytes read for `MaxDocumentByteCount`.
- **After `TrySkip` returns `false`, the state is taken just after the start tag.** A reader created from it reads the element's content token by token. To skip the element whole in the next block, take the state from a copy of the reader made before the `Read` that reached the start tag. See [Skip elements](/xmlessentials/guides/use-utf8xmlreader#skip-elements).
- **The options can't change mid-document.** The state carries them, and every reader created from the state uses them.
- **What your code knows isn't in the state.** Which element you're inside, and what you've collected so far, belong in your own variables.
