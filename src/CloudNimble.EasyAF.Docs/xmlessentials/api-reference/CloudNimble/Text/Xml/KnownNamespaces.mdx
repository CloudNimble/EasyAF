## Summary

Provides the namespace declarations of well-known XML formats, each as the prefixes the format is
customarily written with and the namespace URIs they are bound to.

## Usage

`KnownNamespaces` holds the namespace declarations of well-known XML formats, each as the prefixes the format is customarily written with and the namespace URIs they're bound to. Assign one to `XmlSerializerOptions.Namespaces`, and the serializer declares every namespace of the set on the document element and writes each element and attribute in one of them with the set's prefix.

In the sample, `PodcastShow` is written as `rss`, and its `Author` property is an element in the iTunes namespace:

```csharp
var options = new XmlSerializerOptions { Namespaces = KnownNamespaces.Podcast, WriteIndented = true, NewLine = "\n", OmitXmlDeclaration = true };
var show = new PodcastShow { Title = "Field Notes", Author = "Contoso Radio" };

output.WriteLine(XmlSerializer.Serialize(show, options));
```

```xml
<rss xmlns:atom="http://www.w3.org/2005/Atom" xmlns:content="http://purl.org/rss/1.0/modules/content/" xmlns:dc="http://purl.org/dc/elements/1.1/" xmlns:googleplay="http://www.google.com/schemas/play-podcasts/1.0" xmlns:itunes="http://www.itunes.com/dtds/podcast-1.0.dtd" xmlns:media="http://search.yahoo.com/mrss/" xmlns:podcast="https://podcastindex.org/namespace/1.0" xmlns:psc="http://podlove.org/simple-chapters" xmlns:sy="http://purl.org/rss/1.0/modules/syndication/">
  <itunes:author>Contoso Radio</itunes:author>
  <title>Field Notes</title>
</rss>
```

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/14_Namespaces.cs)

What to know:

- **Every declaration of the set is written,** whether or not the document uses it. The sample uses only `itunes`.
- **A set holds the namespaces a format adds to its own.** A format whose own elements have no namespace, such as RSS, or are customarily in the default namespace, such as a sitemap, isn't in its set.
- **The sets are read-only,** and their declarations are in alphabetical order of prefix.
- **The prefixes matter only when the serializer writes.** When it reads, it compares namespace URIs, so a document that uses other prefixes reads the same.
- **To use the prefixes of a particular document instead,** pass it to `XmlDocument.DiscoverNamespaces` and assign the result to `XmlSerializerOptions.Namespaces`.

For the other ways to choose prefixes, see [Use XML namespaces](/xmlessentials/guides/namespaces).

## Remarks

Assign one of these to [XmlSerializerOptions.Namespaces](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlSerializerOptions#namespaces) to have the serializer declare the
namespaces on the document element and write the customary prefixes. Every declaration of a set is
written, whether or not the document uses it. The sets are read-only, and their declarations are in
alphabetical order of prefix.

A set holds the namespaces a format adds to its own. A format whose own elements have no namespace, such
as RSS, or are customarily written in the default namespace, such as a sitemap, is not in its set. To use
the prefixes of a particular document instead, see
[XmlDocument.DiscoverNamespaces](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlDocument#discovernamespaces).
