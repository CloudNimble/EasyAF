## Summary

Provides options to be used with [XmlSerializer](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlSerializer). This class cannot be inherited.

## Usage

`XmlSerializerOptions` holds the settings that control how [`XmlSerializer`](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlSerializer) writes and reads XML: names, indentation, null handling, limits, converters, and where type metadata comes from. It is the counterpart of `JsonSerializerOptions`.

Create an instance once, set its properties in the initializer, and pass the same instance to every call:

```csharp
private static readonly XmlSerializerOptions s_compact = new()
{
    OmitXmlDeclaration = true,
    PropertyNamingPolicy = XmlNamingPolicy.CamelCase,
};
```

```csharp
output.WriteLine(XmlSerializer.Serialize(new InvoiceLine { Sku = "KB-101", Quantity = 2 }, s_compact));
output.WriteLine(XmlSerializer.Serialize(new InvoiceCustomer { Name = "Contoso", Email = "ap@contoso.example" }, s_compact));
```

The code produces the following output:

```xml
<invoiceLine><sku>KB-101</sku><quantity>2</quantity></invoiceLine>
<invoiceCustomer><name>Contoso</name><email>ap@contoso.example</email></invoiceCustomer>
```

There are three ways to get an instance:

- `new XmlSerializerOptions()` for the general defaults, or `new XmlSerializerOptions(XmlSerializerDefaults.Web)`, `XmlSerializerDefaults.Strict`, or `XmlSerializerDefaults.Bcl` for the other three sets.
- `new XmlSerializerOptions(existing)` to copy an instance and change the copy.
- The shared, read-only instances `XmlSerializerOptions.Default`, `XmlSerializerOptions.Web`, `XmlSerializerOptions.Strict`, and `XmlSerializerOptions.Bcl`.

An instance becomes read-only the first time it is used, or when you call `MakeReadOnly`. Every option, with its default, is listed in [Configure XmlSerializerOptions](/xmlessentials/guides/configure-options).

## Remarks

This class is the XML counterpart of `System.Text.Json.JsonSerializerOptions`.
An instance becomes read-only the first time it is used to serialize or deserialize, or when
[XmlSerializerOptions.MakeReadOnly](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlSerializerOptions#makereadonly) is called. Create one instance and reuse it: the converters and type info it
resolves are cached on the instance.

## Examples

The following examples show the three ways to get an options instance and what happens once an instance is in use.

### Use the built-in instances

```csharp
var line = new InvoiceLine { Sku = "KB-101", Quantity = 2 };

output.WriteLine(XmlSerializer.Serialize(line, XmlSerializerOptions.Default));
output.WriteLine(XmlSerializer.Serialize(line, XmlSerializerOptions.Web));
output.WriteLine(XmlSerializer.Serialize(line, XmlSerializerOptions.Strict));
```

The code produces the following output:

```xml
<?xml version="1.0" encoding="utf-8"?><InvoiceLine><Sku>KB-101</Sku><Quantity>2</Quantity></InvoiceLine>
<invoiceLine><sku>KB-101</sku><quantity>2</quantity></invoiceLine>
<?xml version="1.0" encoding="utf-8"?><InvoiceLine><Sku>KB-101</Sku><Quantity>2</Quantity></InvoiceLine>
```

### Start from a set of defaults and copy an instance

```csharp
var web = new XmlSerializerOptions(XmlSerializerDefaults.Web)
{
    WriteIndented = true,
    NewLine = "\n",
};

var line = new InvoiceLine { Sku = "KB-101", Quantity = 2 };
output.WriteLine(XmlSerializer.Serialize(line, web));

var flat = new XmlSerializerOptions(web) { WriteIndented = false };
output.WriteLine($"Source is read-only: {web.IsReadOnly}. Copy is read-only: {flat.IsReadOnly}.");
output.WriteLine(XmlSerializer.Serialize(line, flat));
```

The code produces the following output:

```text
<invoiceLine>
  <sku>KB-101</sku>
  <quantity>2</quantity>
</invoiceLine>
Source is read-only: True. Copy is read-only: False.
<invoiceLine><sku>KB-101</sku><quantity>2</quantity></invoiceLine>
```

### See when an instance becomes read-only

```csharp
var options = new XmlSerializerOptions { OmitXmlDeclaration = true };
output.WriteLine($"Before first use: {options.IsReadOnly}");

XmlSerializer.Serialize(new InvoiceLine { Sku = "KB-101", Quantity = 2 }, options);
output.WriteLine($"After first use: {options.IsReadOnly}");

try
{
    options.WriteIndented = true;
}
catch (InvalidOperationException ex)
{
    output.WriteLine(ex.Message);
}

var frozen = new XmlSerializerOptions();
frozen.MakeReadOnly();
output.WriteLine($"After MakeReadOnly: {frozen.IsReadOnly}");
```

The code produces the following output:

```text
Before first use: False
After first use: True
This XmlSerializerOptions instance is read-only.
After MakeReadOnly: True
```

## Best Practices

- **Create options once.** Keep each instance in a `static readonly` field or a singleton. Never create one per call: the type metadata is cached on the instance, and a new instance starts with none.
- **Set everything in the initializer.** An instance can't be changed after its first use, so finish configuring it where you create it.
- **Use the same instance to read and to write.** Naming policies, the default property mapping, and the default namespace change the names the serializer looks for when it reads.
- **Call `MakeReadOnly` before you share an instance** with code that might otherwise change it before its first use.
- **Copy at startup, not per call.** A copy shares none of the source's cached metadata.
- **Set `NewLine` when the output must be identical on every operating system.** Its default is `Environment.NewLine`, and it is written for every line break: the ones `WriteIndented` adds and the ones inside values. It accepts `"\n"` and `"\r\n"`.
- **Set the layout options to match the files you already have.** `EmptyElementStyle` chooses between `<e/>`, `<e />` and `<e></e>`, and `AttributeStyle` with `AttributesPerLine` chooses how the attributes of a start tag are laid out. They change how the output looks, not what a reader gets from it, and they are passed to the writer under the same names.
- **Start from `XmlSerializerOptions.Strict` for XML you don't control,** and set `MaxDocumentByteCount`. See [Security](/xmlessentials/guides/security).

## Considerations

An options instance carries a cache as well as settings, which explains most of what follows.

### Read-only after first use

Serializing, deserializing, or calling `GetTypeInfo` or `TryGetTypeInfo` makes the instance read-only. From then on every setter throws an `InvalidOperationException` with the message `This XmlSerializerOptions instance is read-only.`, and so do changes to `Converters` and `TypeInfoResolverChain`. The four static instances are read-only from the start. To change a read-only instance, copy it with `new XmlSerializerOptions(existing)`.

### The resolver is given, not assumed

`TypeInfoResolver` is `null` on a new instance. `GetTypeInfo` and `TryGetTypeInfo` use the resolver the instance has, and throw an `InvalidOperationException` when it has none. The members that need reflection give an instance without a resolver the reflection resolver: every `XmlSerializer` method that takes options, `GetConverter`, `MakeReadOnly(populateMissingResolver: true)`, and the four static instances. Each of them carries `RequiresUnreferencedCode` and `RequiresDynamicCode`, so a trimmed or Native AOT application gets a warning where it uses one. A copy made with `new XmlSerializerOptions(existing)` keeps a resolver you set, and not one that was only given: a copy of `XmlSerializerOptions.Web` has none, so a context you create from it becomes its resolver.

### The cache lives on the instance

Each instance caches the converter and the type metadata for every type it has been used with. A call with a new instance builds that metadata again, which costs many times what the call itself costs. See [Benchmarks](/xmlessentials/benchmarks). The cache is never trimmed, so an application that keeps creating instances also keeps their metadata alive for as long as it holds them.

### Zero means the built-in default

`IndentSize`, `DefaultBufferSize`, and the `Max*` limits are `0` on a new instance. For each of them, `0` selects the built-in value: an indent of 2, a 16,384-byte buffer, a depth of 64, 1,000 attributes, 1,024 bytes for a name, 16,777,216 bytes for a text value, and 1,048,576 bytes for a comment. `MaxDocumentByteCount` is the exception: `0` means no limit.

### Closed types

`InferClosedTypePolymorphism` takes the derived types of a closed type from the list the compiler makes, for a type that declares none with `[XmlDerivedType<T>]`. It is `false` by default, as in System.Text.Json. A closed type needs C# 15 and .NET 11. See [Infer the derived types of a closed type](/xmlessentials/guides/polymorphism#infer-the-derived-types-of-a-closed-type).

### Differences from JsonSerializerOptions

- `XmlSerializerDefaults.Web` sets only `PropertyNamingPolicy` to camelCase and `OmitXmlDeclaration` to `true`. It doesn't turn on case-insensitive matching.
- `RespectRequiredConstructorParameters` defaults to `true`.
- There are three naming policies for members instead of one: `PropertyNamingPolicy`, and `ElementNamingPolicy` and `AttributeNamingPolicy`, which override it for their kind of name.
- XML has options that JSON has no use for, such as `DefaultPropertyMapping`, `DefaultNamespace`, `OmitXmlDeclaration`, and `XmlVersion`.

### Thread safety

A read-only instance is meant to be shared between threads. See [Thread safety](/xmlessentials/guides/thread-safety).

### <Icon icon="tag" iconType="duotone" color="#419AC5" size={24} className="mr-2" /> Namespaces

Gets or sets the namespace declarations that are written on the document element, each as a prefix
and the namespace URI it is bound to.

#### Syntax

```csharp
public System.Collections.Generic.IReadOnlyDictionary<string, string> Namespaces { get; set; }
```

#### Property Value

Type: `System.Collections.Generic.IReadOnlyDictionary<string, string>?`
The declarations, keyed by prefix, in the order they are written, or [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null) for none.
An empty prefix is the default namespace. The default is [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null).

#### Exceptions

| Exception | Description |
|-----------|-------------|
| `ArgumentException` | The property is set to declarations of which one cannot be written: a prefix that is not an XML name
without a colon, the `xmlns` prefix, the `xml` prefix or its namespace bound to anything but
each other, the `xmlns` namespace, or a namespace URI that is [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null) or empty. |
| `InvalidOperationException` | The property is set after this instance has become read-only. |

#### Examples

```csharp
var options = new XmlSerializerOptions { Namespaces = KnownNamespaces.Podcast };
string xml = XmlSerializer.Serialize(feed, options);
```

#### Remarks

Without this property the serializer declares a namespace where it is first needed and chooses how:
as the default namespace of an element, or with a generated prefix such as `ns1` for an attribute.
A namespace that is declared here is in scope for the whole document, so every element and attribute
in it is written with the prefix given here. A declaration is written whether or not anything uses it.
When two prefixes are bound to one namespace, the one declared last is used. The declarations are
written in the order given, with one exception: the declaration that names the namespace of the
document element itself comes first, because the element's start tag needs it.

The declarations are copied when the property is set. Use
[XmlDocument.DiscoverNamespaces](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlDocument#discovernamespaces) to take them from
an existing document, [KnownNamespaces](/xmlessentials/api-reference/CloudNimble/Text/Xml/KnownNamespaces) for those of a well-known format, or
[XmlNamespaceDeclarationAttribute](/xmlessentials/api-reference/CloudNimble/Text/Xml/Serialization/XmlNamespaceDeclarationAttribute) to state them on the type. These declarations take
precedence over the type's.

An empty prefix declares the default namespace on the document element, so an element with no
namespace of its own is in that namespace. When the document element has a namespace of its own that
is not this one and has no prefix declared, the two cannot both be written, and serialization throws an
[InvalidOperationException](https://learn.microsoft.com/dotnet/api/system.invalidoperationexception).

The property affects writing only. When the serializer reads, it compares namespace URIs and never
prefixes.
