## Summary

Specifies that a member is serialized as a child element of type *T*. This class cannot be inherited.

## Usage

Apply `[XmlElement]` to a property or field to say that it is a child element and, optionally, to set the element's name, namespace, or order. A member is an element by default, so you need the attribute in three cases:

- To name the element, as an alternative to `[XmlPropertyName]`.
- To keep one member as an element when `XmlSerializerOptions.DefaultPropertyMapping` is `XmlPropertyMapping.Attribute`.
- To set `Namespace` or `Order`.

```csharp
[XmlElement("unit-price")]
public decimal UnitPrice { get; set; }
```

On a collection that has no `[XmlArray]`, the name applies to each repeated item:

```csharp
public sealed class NewsFeed
{
    public string? Title { get; set; }

    [XmlElement("Entry")]
    public List<string> Entries { get; set; } = [];
}
```

```csharp
var feed = new NewsFeed { Title = "Releases", Entries = ["1.0.0 is out", "1.0.1 fixes a typo"] };
var options = new XmlSerializerOptions { WriteIndented = true, NewLine = "\n", OmitXmlDeclaration = true };

string xml = XmlSerializer.Serialize(feed, options);
output.WriteLine(xml);
```

The code produces the following output:

```xml
<NewsFeed>
  <Title>Releases</Title>
  <Entry>1.0.0 is out</Entry>
  <Entry>1.0.1 fixes a typo</Entry>
</NewsFeed>
```

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/12_SerializeCollections.cs)

## Type Parameters

- `T` - The type that is serialized with the element name.

## Considerations

- `[XmlPropertyName]` on the same member takes precedence over `ElementName`, and `[XmlPropertyOrder]` takes precedence over `Order`.
- A name set here isn't converted by a naming policy.
- `Order` follows the rules of `[XmlPropertyOrder]`: values of zero or more are written first in ascending order, and a negative value, the default, means the order isn't set.
- A member can't be both an element and something else. `[XmlElement]` together with `[XmlAttribute]`, `[XmlText]`, or `[XmlCData]` throws a `NotSupportedException` the first time the type is used.
- Several `[XmlElement<T>]` on one member make a choice of elements: each element name stands for a type, a value is written under the element of its type, and an element is read as the type of its name. On a collection, each item is written under the element of its own type. A value of the member's own type is written under the member's name. When two elements hold the same type, declare the member as `XmlNamedValue`, or a collection of it, so each value carries the name of its element. See [Polymorphism](/xmlessentials/guides/polymorphism).
- A member can have one `[XmlElement]` without a type argument. A second one, or one next to `[XmlElement<T>]`, throws a `NotSupportedException` the first time the type is used.

### <Icon icon="tag" iconType="duotone" color="#419AC5" size={24} className="mr-2" /> Namespace <Badge color="gray">Inherited</Badge>

Gets or sets the namespace URI of the element.

#### Syntax

```csharp
public string Namespace { get; set; }
```

#### Property Value

Type: `string?`
The namespace URI of the element. If the value is [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null), the element is written with an unqualified name,
so it is in the default namespace that is in scope. An empty string puts the element in no namespace.
The default is [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null).

#### Remarks

An element in no namespace is written with `xmlns=""` where a default namespace is in scope, and
only an element in no namespace is read as the member.
