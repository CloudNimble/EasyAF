## Summary

Indicates, when placed on a type declaration, that *T* is opted into polymorphic serialization
and can appear where the annotated type is expected. This class cannot be inherited.

## Usage

`XmlDerivedTypeAttribute` is the abstract base of `XmlDerivedTypeAttribute<T>`, which is the attribute you apply. Put one `[XmlDerivedType<T>]` on a base class for each derived type that can appear where the base type is declared.

```csharp
[XmlPolymorphic]
[XmlDerivedType<Book>]
[XmlDerivedType<Dvd>("Disc")]
public class Product
{
    public string? Title { get; set; }
}
```

- `[XmlDerivedType<Book>]` uses the type's name, `Book`, as the discriminator.
- `[XmlDerivedType<Dvd>("Disc")]` sets the discriminator to `Disc`.

What the discriminator is depends on `XmlPolymorphicAttribute.DiscriminatorPlacement`: the name of the element, the value of a named attribute, or the value of `xsi:type`. With the default placement, a `Dvd` in a list of products is written as `<Disc>`:

```xml
<Disc>
  <Title>The Matrix</Title>
  <Runtime>136</Runtime>
</Disc>
```

See [Serialize derived classes](/xmlessentials/guides/polymorphism) and the [polymorphism sample](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/16_Polymorphism.cs).

## Type Parameters

- `T` - The derived type that is supported in polymorphic serialization of the annotated type.

## Considerations

- The type argument is checked by the compiler, which is why the attribute is generic. The serializer doesn't verify that `T` derives from the type the attribute is on, so keep the two in the same hierarchy.
- The discriminator is always a string. `TypeDiscriminator` is typed as `object` to match the shape of `JsonDerivedTypeAttribute`, but there is no integer form.
- When the discriminator is an element name, the element naming policy of the options is applied to it. When it is an attribute value, it is written as declared.
- `Namespace` is the namespace of the element that is named for the derived type. Left `null`, the element is written under its name alone, in the default namespace that is in scope. An empty string puts it in no namespace.
- A derived type that has a namespace is matched by its local name and its namespace when a document is read, so two derived types can have one local name in two namespaces. A derived type with no namespace is matched by its local name alone.
- `Namespace` applies when the discriminator is the element name. With `XmlDiscriminatorPlacement.Attribute` or `XsiType` there is no such element, and a `Namespace` that isn't `null` throws a `NotSupportedException` the first time the type is used.
- In `System.Xml.Serialization`, the same job is done by `[XmlInclude(typeof(T))]`. In this library `[XmlInclude]` means something else: it opts a non-public member in to serialization.

#### Property Value

Type: `string?`
The namespace URI. The default is [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null), which writes the element under its name
alone, so it is in the default namespace that is in scope. An empty string puts the element in no
namespace.

#### Remarks

The value applies when the derived type is identified by the name of its element, which is
[XmlDiscriminatorPlacement.ElementName](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlDiscriminatorPlacement). With another placement there is no such element,
and a value that is not [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null) is refused with a [NotSupportedException](https://learn.microsoft.com/dotnet/api/system.notsupportedexception)
the first time the type is used.

When a document is read, a derived type that has a namespace is matched by its local name and its
namespace, so two derived types can have one local name in two namespaces. A derived type with no
namespace is matched by its local name alone.
