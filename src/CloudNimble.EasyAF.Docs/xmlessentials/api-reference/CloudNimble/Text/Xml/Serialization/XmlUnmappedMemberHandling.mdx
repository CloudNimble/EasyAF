## Summary

Specifies how [XmlSerializer](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlSerializer) handles XML elements and attributes that cannot be mapped to a specific
.NET member when deserializing object types.

## Usage

`XmlUnmappedMemberHandling` says what the serializer does, when reading, with an element or attribute that no member of the target type maps to. Set it through `XmlSerializerOptions.UnmappedMemberHandling`. It is the counterpart of `JsonUnmappedMemberHandling`.

| Value | Behavior |
| --- | --- |
| `Skip` (default) | The element or attribute is ignored. |
| `Disallow` | The serializer throws an [`XmlException`](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlException). |

```csharp
string[] documents =
[
    "<Registration><Email>ada@contoso.example</Email><Plan>pro</Plan><Coupon>SPRING</Coupon></Registration>",
    "<Registration source=\"web\"><Email>ada@contoso.example</Email><Plan>pro</Plan></Registration>",
];

var options = new XmlSerializerOptions { UnmappedMemberHandling = XmlUnmappedMemberHandling.Disallow };

foreach (string xml in documents)
{
    Registration? registration = XmlSerializer.Deserialize<Registration>(xml);
    output.WriteLine($"Skip: {registration!.Email} chose {registration.Plan}");

    try
    {
        XmlSerializer.Deserialize<Registration>(xml, options);
    }
    catch (XmlException ex)
    {
        output.WriteLine($"Disallow: {ex.Message}");
    }
}
```

The code produces the following output:

```text
Skip: ada@contoso.example chose pro
Disallow: Unknown element 'Coupon'. Path: /Registration | LineNumber: 1 | BytePositionInLine: 73.
Skip: ada@contoso.example chose pro
Disallow: Unknown attribute 'source'. Path: /Registration | LineNumber: 1 | BytePositionInLine: 28.
```

## Remarks

When the type has a member marked with [XmlExtensionDataAttribute](/xmlessentials/api-reference/CloudNimble/Text/Xml/Serialization/XmlExtensionDataAttribute), or a member marked with
[XmlMixedAttribute](/xmlessentials/api-reference/CloudNimble/Text/Xml/Serialization/XmlMixedAttribute) for elements, that member captures the unmapped content and neither value applies.

## Considerations

- The setting is on the options and applies to every type in the object graph. There is no attribute that sets it for one type.
- Namespace declarations, `xsi:nil`, `xsi:type`, and the attributes the serializer itself writes for polymorphism and preserved references are never treated as unmapped.
- A member marked `[XmlIgnore]` isn't mapped, so with `Disallow` an element for it is an error.
- When the type has an `[XmlExtensionData]` member, unmapped elements and attributes are collected there, and `Disallow` doesn't reject them.
- Names are matched with case unless `PropertyNameCaseInsensitive` is `true`, so with `Disallow` an element that differs from a member only by case is an error.
- `XmlSerializerOptions.Strict` sets `Disallow`.

## Values

| Name | Value | Description |
|------|-------|-------------|
| `Skip` | 0 | Silent skipping of any unmapped element or attribute. This is the default behavior. |
| `Disallow` | 1 | Rejection of any unmapped element or attribute with an [XmlException](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlException). |
