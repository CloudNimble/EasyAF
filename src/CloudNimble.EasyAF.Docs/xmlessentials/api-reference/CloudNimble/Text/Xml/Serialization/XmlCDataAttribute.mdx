## Summary

Specifies that a member is serialized as the text content of the element for its containing type, written as a CDATA section. This class cannot be inherited.

## Usage

Put `[XmlCData]` on a member to make it the text of its containing element, written as a CDATA section. A CDATA section holds characters such as `<` and `&` without escaping, which keeps embedded code or markup readable.

```csharp
public sealed class Script
{
    [XmlAttribute("language")]
    public string? Language { get; set; }

    [XmlCData]
    public string? Code { get; set; }
}
```

```csharp
var options = new XmlSerializerOptions { OmitXmlDeclaration = true };
var script = new Script { Language = "js", Code = "if (a < b && b > 0) { run(); }" };

string xml = XmlSerializer.Serialize(script, options);
output.WriteLine(xml);

Script? copy = XmlSerializer.Deserialize<Script>(xml, options);
output.WriteLine(copy!.Code);
```

The code produces the following output:

```text
<Script language="js"><![CDATA[if (a < b && b > 0) { run(); }]]></Script>
if (a < b && b > 0) { run(); }
```

The member doesn't get an element of its own: `Code` is the content of `<Script>`. The other members of the type are attributes.

[View the complete sample on GitHub](https://github.com/CloudNimble/XmlEssentials/blob/main/src/CloudNimble.XmlEssentials.Samples/18_MixedContent.cs)

## Remarks

The member must have a simple type: a type with a built-in value converter, an enumeration, or the nullable form of
either. A type can map one member with this attribute or [XmlTextAttribute](/xmlessentials/api-reference/CloudNimble/Text/Xml/Serialization/XmlTextAttribute), and that type cannot also
map members to child elements.

## Considerations

- `[XmlCData]` follows the rules of `[XmlText]`. A type can have one member with either attribute, and it can't also have members mapped to child elements. The serializer throws `NotSupportedException` otherwise.
- The member must have a simple type: a type with a built-in value converter, an enumeration, or the nullable form of either.
- The attribute affects writing only. When reading, escaped text and CDATA sections are accepted alike, so `<Script>a &lt; b</Script>` gives the same value as the CDATA form.
- A value that contains `]]>` is split at each `]]>` and written as several sections: `a]]>b` is written as `<![CDATA[a]]]]><![CDATA[>b]]>`. A reader joins them again, and the value reads back as it was.
- A `null` value writes no content, which leaves the element empty.
- CDATA is a way of writing text, not a different kind of data. A consumer that parses the document sees the same characters either way.
