## Summary

Indicates, when placed on a type, that the type is serialized polymorphically, and specifies how its type discriminator
is written. This class cannot be inherited.

## Usage

Put `[XmlPolymorphic]` on a base class to say how its derived types are told apart in a document, and add one `[XmlDerivedType<T>]` for each derived type that is allowed. The pair corresponds to `[JsonPolymorphic]` and `[JsonDerivedType]` in System.Text.Json.

```csharp
[XmlPolymorphic]
[XmlDerivedType<Book>]
[XmlDerivedType<Dvd>("Disc")]
public class Product
{
    public string? Title { get; set; }
}
```

| Property | Purpose | Default |
| --- | --- | --- |
| `DiscriminatorPlacement` | Where the type discriminator is written: the element name, a named attribute, or `xsi:type`. | `ElementName` |
| `TypeDiscriminatorPropertyName` | The name of the discriminator attribute. Required with `XmlDiscriminatorPlacement.Attribute`, and not used otherwise. | `null` |
| `UnknownDerivedTypeHandling` | What happens to a runtime type, or a discriminator in a document, that isn't declared. | `FailSerialization` |
| `InferClosedTypePolymorphism` | Whether the derived types of a closed type are inferred. Not set by default, which leaves it to `XmlSerializerOptions.InferClosedTypePolymorphism`. | Not set |

With the default placement, `[XmlPolymorphic]` itself is optional: `[XmlDerivedType<T>]` attributes alone give the same result. Add `[XmlPolymorphic]` to choose another placement or another way to handle undeclared types.

See [Serialize derived classes](/xmlessentials/guides/polymorphism) for a walkthrough.

## Examples

### Serialize a list of a base type

Each derived type is written under its own element name, and is read back as the same type. An object of the base type keeps the member's element name.

```csharp
var options = new XmlSerializerOptions { WriteIndented = true, NewLine = "\n" };
var catalog = new Catalog
{
    Products =
    [
        new Book { Title = "Clean Code", Author = "Robert C. Martin" },
        new Dvd { Title = "The Matrix", Runtime = 136 },
        new Product { Title = "Gift card" },
    ],
};

string xml = XmlSerializer.Serialize(catalog, options);
output.WriteLine(xml);

Catalog? copy = XmlSerializer.Deserialize<Catalog>(xml, options);
foreach (Product product in copy!.Products)
{
    output.WriteLine($"{product.GetType().Name}: {product.Title}");
}
```

The code produces the following output:

```xml
<?xml version="1.0" encoding="utf-8"?>
<Catalog>
  <Book>
    <Title>Clean Code</Title>
    <Author>Robert C. Martin</Author>
  </Book>
  <Disc>
    <Title>The Matrix</Title>
    <Runtime>136</Runtime>
  </Disc>
  <Products>
    <Title>Gift card</Title>
  </Products>
</Catalog>
Book: Clean Code
Dvd: The Matrix
Product: Gift card
```

### Use xsi:type and fall back to an ancestor

```csharp
[XmlPolymorphic(DiscriminatorPlacement = XmlDiscriminatorPlacement.XsiType, UnknownDerivedTypeHandling = XmlUnknownDerivedTypeHandling.FallBackToNearestAncestor)]
[XmlDerivedType<Car>]
[XmlDerivedType<Truck>]
public class Vehicle
{
    public string? Make { get; set; }
}
```

```csharp
var options = new XmlSerializerOptions { OmitXmlDeclaration = true };

Vehicle truck = new Truck { Make = "Northwind", Payload = 12000 };
output.WriteLine(XmlSerializer.Serialize(truck, options));

Vehicle sportsCar = new SportsCar { Make = "Contoso", Doors = 2, TopSpeed = 310 };
string xml = XmlSerializer.Serialize(sportsCar, options);
output.WriteLine(xml);

Vehicle? copy = XmlSerializer.Deserialize<Vehicle>(xml, options);
output.WriteLine(copy!.GetType().Name);
```

`SportsCar` derives from `Car` and isn't declared, so it is written as a `Car`. The code produces the following output:

```text
<Vehicle xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:type="Truck"><Make>Northwind</Make><Payload>12000</Payload></Vehicle>
<Vehicle xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:type="Car"><Make>Contoso</Make><Doors>2</Doors></Vehicle>
Car
```

## Best Practices

- Declare every derived type that can appear. The default, `FailSerialization`, then reports a type you forgot instead of writing part of it.
- Prefer `ElementName` when you control the format. It needs no extra attribute, and the document says what each element is.
- Use `Attribute` or `XsiType` when a schema fixes the element name.
- Choose a fallback value of `UnknownDerivedTypeHandling` only when losing the members of the undeclared type is acceptable.
- Give each derived type a discriminator that is not the element name of another member of the containing type.

## Considerations

- The declared base type can be a concrete class, an abstract class, or an interface. An abstract class or an interface must list its derived types with `[XmlDerivedType<T>]`. When the serializer reads an element that doesn't identify one of them, it throws `XmlException`, because it can't create the declared type.
- Derived types inherit the attribute and the list of derived types. A value whose type is the declared type, such as a `Book` serialized as a `Book` or held by a member declared as `Book`, is written with no discriminator. A type below the declared type is still identified, so a value of a type derived from `Book` is written with its discriminator.
- `InferClosedTypePolymorphism` takes the derived types of a closed type from the list the compiler makes. Set to `true`, it infers for the type whatever `XmlSerializerOptions.InferClosedTypePolymorphism` says; set to `false`, it turns inference off for the type. On a type that isn't closed, `true` throws an `InvalidOperationException` the first time the type is used. A closed type needs C# 15 and .NET 11.
- A source-generated context reads and writes derived types as the reflection resolver does. Listing the base type on the context also covers the derived types it declares.
- The mapping is built once for each `XmlSerializerOptions` instance and cached. There is no API to add derived types at run time.

### <Icon icon="tag" iconType="duotone" color="#419AC5" size={24} className="mr-2" /> InferClosedTypePolymorphism

Gets or sets a value that indicates whether the derived types of a closed type are inferred.

#### Syntax

```csharp
public bool InferClosedTypePolymorphism { get; set; }
```

#### Property Value

Type: `bool`
[`true`](https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/bool) if the derived types of the type are taken from its closed hierarchy;
[`false`](https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/bool) if they are not, whatever the options say. When the property is not set,
[XmlSerializerOptions.InferClosedTypePolymorphism](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlSerializerOptions#inferclosedtypepolymorphism) decides. The getter returns
[`false`](https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/bool) for a property that is not set.

#### Remarks

A closed type is a class declared with the `closed` modifier, which needs C# 15 and
.NET 11. Its derived types are all in its own assembly, and the compiler lists them. With this
property, a derived type is written and read as if the type had an
[XmlDerivedTypeAttribute](/xmlessentials/api-reference/CloudNimble/Text/Xml/Serialization/XmlDerivedTypeAttribute) for it, with the name of the derived type as its discriminator.

Derived types that are declared with [XmlDerivedTypeAttribute](/xmlessentials/api-reference/CloudNimble/Text/Xml/Serialization/XmlDerivedTypeAttribute) are the whole list: nothing
is inferred for a type that declares one.

Setting the property to [`true`](https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/bool) on a type that is not closed throws an
[InvalidOperationException](https://learn.microsoft.com/dotnet/api/system.invalidoperationexception) the first time the type is used.
