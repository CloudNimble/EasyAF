## Summary

Indicates, when placed on a member of type [XmlExtensionData](/xmlessentials/api-reference/CloudNimble/Text/Xml/Serialization/XmlExtensionData), that XML attributes and child elements that have
no matching member are added to that member during deserialization. This class cannot be inherited.

## Usage

Put `[XmlExtensionData]` on a member of type `XmlExtensionData` to keep the attributes and elements that no other member of the type maps. Without such a member, the serializer skips that content, or rejects it when `XmlSerializerOptions.UnmappedMemberHandling` is `Disallow`. The attribute corresponds to `[JsonExtensionData]` in System.Text.Json.

```csharp
public sealed class Settings
{
    public string? Theme { get; set; }

    [XmlExtensionData]
    public XmlExtensionData? Extra { get; set; }
}
```

After deserializing, `Extra.Attributes` and `Extra.Elements` hold what the document had beyond `Theme`. When you serialize the object, that content is written back. See `XmlExtensionData` for an example with its output, and [Mixed content and overflow](/xmlessentials/guides/mixed-content#keep-content-that-no-member-maps) for the walkthrough.

## Remarks

The member must be of type [XmlExtensionData](/xmlessentials/api-reference/CloudNimble/Text/Xml/Serialization/XmlExtensionData), and a type can have only one member with this attribute.
The reflection-based serializer throws a [NotSupportedException](https://learn.microsoft.com/dotnet/api/system.notsupportedexception) when either rule is broken.

## Considerations

- The member must be of type `XmlExtensionData`. On a member of any other type, the serializer throws `NotSupportedException` when it builds the type's metadata. A dictionary is not accepted.
- A type can have one extension data member. A second one also throws `NotSupportedException`.
- The member isn't written as an element of its own. Its content is written directly into the containing element.
- If the document has no unmapped content, the member isn't assigned. If the member already holds an object when content is captured, the content is added to that object, so a get-only member that the type initializes works too.
- A type with an extension data member accepts unmapped content even when `UnmappedMemberHandling` is `Disallow`.
- Don't combine it with `[XmlMixed]` on the same type. In a mixed-content type every child element goes to the mixed list, so no element reaches the extension data.
