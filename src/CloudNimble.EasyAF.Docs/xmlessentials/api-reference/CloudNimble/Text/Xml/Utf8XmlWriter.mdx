## Summary

Provides a forward-only, non-cached writer for UTF-8 encoded XML text. This class cannot be inherited.

## Usage

Create a writer over an `IBufferWriter<byte>` or a `Stream`, write the document with one call per start tag, attribute, value, and end tag, and dispose the writer to flush it.

```csharp
var buffer = new ArrayBufferWriter<byte>();
var options = new XmlWriterOptions { Indented = true, NewLine = "\n" };

using (var writer = new Utf8XmlWriter(buffer, options))
{
    writer.WriteStartElement("Order");
    writer.WriteAttributeString("id", "1042");

    writer.WriteStartElement("Customer");
    writer.WriteStringValue("Ada Lovelace");
    writer.WriteEndElement();

    writer.WriteStartElement("Total");
    writer.WriteAttributeString("currency", "EUR");
    writer.WriteNumberValue(129.90m);
    writer.WriteEndElement();

    writer.WriteStartElement("Notes");
    writer.WriteEndElement();

    writer.WriteEndElement();
}

output.WriteLine(Encoding.UTF8.GetString(buffer.WrittenSpan));
```

```xml
<?xml version="1.0" encoding="utf-8"?>
<Order id="1042">
  <Customer>Ada Lovelace</Customer>
  <Total currency="EUR">129.90</Total>
  <Notes/>
</Order>
```

Most methods take names and values as a `string`, a `ReadOnlySpan<char>`, or UTF-8 in a `ReadOnlySpan<byte>`, and element names also as an [`XmlEncodedText`](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlEncodedText). Pass an [`XmlWriterOptions`](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlWriterOptions) to the constructor to indent, to leave out the declaration, or to change a limit.

For a walk through every feature, see [How to write XML with Utf8XmlWriter](/xmlessentials/guides/use-utf8xmlwriter).

## Remarks

The API follows the shape of `Utf8JsonWriter`. The writer writes to an [IBufferWriter`1](https://learn.microsoft.com/dotnet/api/system.buffers.ibufferwriter-1)
          or to a [Stream](https://learn.microsoft.com/dotnet/api/system.io.stream), and the output is always UTF-8. Names and values can be passed as strings,
          as spans of characters, or as spans of UTF-8 bytes.
          

A limit on [XmlWriterOptions](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlWriterOptions) that is 0 uses its default: 64 for [XmlWriterOptions.MaxDepth](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlWriterOptions#maxdepth),
1000 for [XmlWriterOptions.MaxAttributeCount](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlWriterOptions#maxattributecount), and 1024 for [XmlWriterOptions.MaxNameByteCount](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlWriterOptions#maxnamebytecount).

[Utf8XmlWriter.Dispose](/xmlessentials/api-reference/CloudNimble/Text/Xml/Utf8XmlWriter#dispose) and [Utf8XmlWriter.DisposeAsync](/xmlessentials/api-reference/CloudNimble/Text/Xml/Utf8XmlWriter#disposeasync) flush the output. If elements are still open and
          [XmlWriterOptions.SkipValidation](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlWriterOptions#skipvalidation) is [`false`](https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/bool), they then throw an
          [XmlException](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlException), so the output written so far is not lost with the error.

var buffer = new ArrayBufferWriter<byte>();

### Write namespaces

Pass the namespace URI, and the writer chooses or declares the prefix.

```csharp
const string atom = "http://www.w3.org/2005/Atom";
const string dublinCore = "http://purl.org/dc/elements/1.1/";
const string shop = "urn:example:shop";

var buffer = new ArrayBufferWriter<byte>();
var options = new XmlWriterOptions { Indented = true, NewLine = "\n", OmitXmlDeclaration = true };

using (var writer = new Utf8XmlWriter(buffer, options))
{
    // The writer declares the default namespace because nothing in scope is bound to it.
    writer.WriteStartElement("feed", atom);

    // Declare a prefix on the root so that every descendant can use it.
    writer.WriteNamespaceDeclaration("dc", dublinCore);

    // The namespace is the default one in scope, so the element needs no prefix.
    writer.WriteElementString("title", atom, "Orders");

    // The namespace is bound to dc, so the writer uses that prefix.
    writer.WriteElementString("creator", dublinCore, "Ada");

    // A prefix and a namespace that are not in scope: the writer declares them on this element.
    writer.WriteStartElement("s", "order", shop);
    writer.WriteAttributeString("s", "id", shop, "1042");
    writer.WriteEndElement();

    // An attribute in a namespace that has no prefix in scope gets a generated one.
    writer.WriteStartElement("entry", atom);
    writer.WriteAttributeString("priority", shop, "high");
    writer.WriteAttributeString("lang", "en");
    writer.WriteEndElement();

    writer.WriteEndElement();
}

output.WriteLine(Encoding.UTF8.GetString(buffer.WrittenSpan));
```

```xml
<feed xmlns="http://www.w3.org/2005/Atom" xmlns:dc="http://purl.org/dc/elements/1.1/">
  <title>Orders</title>
  <dc:creator>Ada</dc:creator>
  <s:order xmlns:s="urn:example:shop" s:id="1042"/>
  <entry xmlns:ns1="urn:example:shop" ns1:priority="high" lang="en"/>
</feed>
```

### Reuse one writer for several documents

```csharp
var buffer = new ArrayBufferWriter<byte>();
using var writer = new Utf8XmlWriter(buffer, new XmlWriterOptions { OmitXmlDeclaration = true });

string[] items = ["Keyboard", "Mouse", "Monitor"];
foreach (var item in items)
{
    writer.WriteStartElement("Item");
    writer.WriteStringValue(item);
    writer.WriteEndElement();
    writer.Flush();

    output.WriteLine($"{Encoding.UTF8.GetString(buffer.WrittenSpan)} ({writer.BytesCommitted} bytes)");

    buffer.ResetWrittenCount();
    writer.Reset();
}

var other = new ArrayBufferWriter<byte>();
writer.Reset(other);
writer.WriteEmptyElement("Done");
writer.Flush();
output.WriteLine($"Second buffer: {Encoding.UTF8.GetString(other.WrittenSpan)}");
```

```text
<Item>Keyboard</Item> (21 bytes)
<Item>Mouse</Item> (18 bytes)
<Item>Monitor</Item> (20 bytes)
Second buffer: <Done/>
```

## Best Practices

- **Dispose the writer, or call `Flush`, before you read the output.** Until then, bytes are pending and the buffer or stream doesn't have them.
- **End every element yourself.** `Dispose` throws an `XmlException` when an element is still open. It doesn't close elements for you.
- **Use the `WriteElement*` methods for elements that hold one value.** One call replaces three.
- **Pass `u8` literals for names that are fixed.** `writer.WriteStartElement("Order"u8)` skips the conversion from UTF-16. For a name computed once at run time, keep an `XmlEncodedText`.
- **Declare the prefixes you use often on the root element** with `WriteNamespaceDeclaration`. Otherwise the writer declares a prefix again on every element that needs it and isn't inside one that has it.
- **Reuse a writer with `Reset` on a hot path.** A reused writer allocates nothing per document. Call `Flush` before `Reset`, because `Reset` discards pending bytes.
- **Set `NewLine` when the bytes matter.** The default depends on the operating system.
- **Write binary data that's in one buffer with one `WriteBase64StringValue` call.** Use `WriteBase64StringSegment` only when the data arrives in pieces.
- **Use `WriteRawValue` only for XML that your own code produced.** The input isn't escaped. By default the writer checks that it's well formed where it goes, but well-formed input can still carry markup you didn't intend.
- **Discard the output when the writer throws.** Part of the document may already be committed.

## Patterns

These are the shapes that code using the writer takes most often.

### Element with attributes and content

Call `WriteStartElement`, then the attributes and namespace declarations, then the content, then `WriteEndElement`. The start tag closes when you write the first content, and attributes aren't accepted after that.

### Leaf element

`WriteElementString`, `WriteElementNumber`, `WriteElementBoolean`, and `WriteElementBase64String` write a start tag, a value, and an end tag in one call. `WriteEmptyElement` writes an element with no content, `<e/>` unless `XmlWriterOptions.EmptyElementStyle` says otherwise, and `WriteNilElement` writes an empty element with `xsi:nil="true"`.

### Attribute with a typed value

`WriteAttributeString` takes text and `WriteAttributeNumber` takes an `int`, a `long`, or a `double`. For any other type, open the attribute with `WriteStartAttribute`, call a value method such as `WriteBooleanValue` or `WriteStringValue(DateTimeOffset)`, and close it with `WriteEndAttribute`.

### One writer, many documents

Create the writer once, and after each document call `Flush` and then `Reset`. `Reset` discards anything that isn't flushed. Use `Reset(IBufferWriter<byte>)` or `Reset(Stream)` to send the next document somewhere else.

### Stream with asynchronous flushes

Write with the synchronous methods, which only fill the writer's buffer, and call `await writer.FlushAsync()` at points where a batch is complete. Dispose with `await using`.

### Copy a parsed document

`XmlDocument.WriteTo` and `XmlElement.WriteTo` write a parsed document, or one element of it, into a writer. See [How to use XmlDocument](/xmlessentials/guides/use-xmldocument).

### Custom converter

`XmlConverter<T>.Write` receives the writer, positioned where the value goes. See [Custom converters](/xmlessentials/guides/custom-converters).

## Considerations

Know the following before you build on the writer.

### Output and buffering

The output is always UTF-8. With an `IBufferWriter<byte>`, the writer writes into memory it gets from the buffer writer and commits it on `Flush`, on `Dispose`, and when it needs more room. With a `Stream`, it fills a buffer rented from the array pool, which starts at 16 KB, and writes to the stream on `Flush`, on `Dispose`, and when the buffer fills. Disposing the writer doesn't close the stream.

### Dispose and open elements

`Dispose` and `DisposeAsync` flush. If an element is still open and `SkipValidation` is `false`, they flush and then throw an `XmlException`. In a `using` statement, that exception replaces an exception that was already on its way out, so the message you catch can be `The document has unclosed elements.` when the real cause came earlier.

### Thread safety

A writer isn't thread safe. Use each instance from one thread at a time. See [Thread safety](/xmlessentials/guides/thread-safety).

### Allocation

A writer that's reused with `Reset` allocates nothing per document. `Reset` discards bytes that are still pending, so call `Flush` first to keep them. See [Benchmarks](/xmlessentials/benchmarks) for the measurements.

### Namespaces

The writer tracks the namespaces in scope and declares what's missing: a default namespace for an element written with a namespace and no prefix, your prefix for an element written with one, and a generated prefix (`ns1`, `ns2`, and so on) for an attribute in a namespace that has no prefix in scope. An element written with no namespace argument, or with a `null` one, gets no declaration, so under a default namespace a reader puts it in that namespace. An element written with an empty namespace is in no namespace: under a default namespace the writer adds `xmlns=""`.

### Indentation

With `Indented` set, elements, comments, and processing instructions each get a line break and indentation. An element that holds text, a CDATA section, or raw XML from `WriteRawValue` is written on one line, with everything in it.

### Layout

Every line break the writer writes is the `NewLine` of its options, including a line feed inside text, a CDATA section, a comment, or a processing instruction. An element with no content is written in the form `EmptyElementStyle` asks for (`<e/>` by default), except after `WriteFullEndElement`, which always writes an end tag. `AttributeStyle` decides whether attributes stay on the line of the start tag.

### What isn't checked

- `WriteRawValue` copies its input without escaping it. It checks that the input is well formed where it is written only when `skipInputValidation` is `false` and the writer does not have `SkipValidation` set.
- With `SkipValidation` set, names, namespace declarations, duplicate attributes, the characters of comments, CDATA sections, and processing instructions, and unclosed elements at `Dispose` aren't checked. Values are still escaped, and the single root, `MaxDepth`, and `MaxAttributeCount` are still enforced.

### Differences from Utf8JsonWriter

- There's no property-name step. Structure comes from `WriteStartElement` and `WriteEndElement`, and attributes are written on the open start tag.
- Validation is on by default and also covers names and namespaces. `SkipValidation` doesn't turn off the single-root check, `MaxDepth`, or `MaxAttributeCount`.
- `Dispose` throws when the document is incomplete.

### Differences from System.Xml.XmlWriter

- The output is UTF-8 only, to an `IBufferWriter<byte>` or a `Stream`. There's no `TextWriter` or `StringBuilder` target.
- There's no `WriteDocType`, `WriteEntityRef`, `WriteStartDocument`, or `WriteEndDocument`. The declaration is written for you, and nothing closes open elements for you.
- `Reset` lets one instance write many documents.
- Typed values have their own methods, in place of `WriteValue` overloads and `XmlConvert`.

### <Icon icon="function" iconType="duotone" color="#419AC5" size={24} className="mr-2" /> WriteBase64StringSegment

Writes a segment of binary data as base64 encoded text to the content of the current element or to the
value of the current attribute.

#### Syntax

```csharp
public void WriteBase64StringSegment(System.ReadOnlySpan<byte> value, bool isFinalSegment)
```

#### Parameters

| Name | Type | Description |
|------|------|-------------|
| `value` | `System.ReadOnlySpan<byte>` | The segment of the binary data to write as base64 encoded text. |
| `isFinalSegment` | `bool` | [`true`](https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/bool) to indicate that this is the final segment of the binary data; otherwise, [`false`](https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/bool). |

#### Exceptions

| Exception | Description |
|-----------|-------------|
| `XmlException` | The writer is not inside an element or an attribute.
-or-
A value of another kind is being written in segments. |
| `ObjectDisposedException` | This instance has been disposed. |

#### Examples

```csharp
writer.WriteStartElement("data");
writer.WriteBase64StringSegment([1], isFinalSegment: false);
writer.WriteBase64StringSegment([2], isFinalSegment: true);
writer.WriteEndElement();
// <data>AQI=</data>
```

#### Remarks

The segments together are written as [Utf8XmlWriter.WriteBase64StringValue](/xmlessentials/api-reference/CloudNimble/Text/Xml/Utf8XmlWriter#writebase64stringvalue) writes the
whole data: one base64 value, padded only at its end. A segment can be any length. The writer keeps the
one or two bytes that do not fill a group of three and encodes them with the next segment. After a
segment that is not final, the next call on the writer must be the next segment, apart from
[Utf8XmlWriter.Flush](/xmlessentials/api-reference/CloudNimble/Text/Xml/Utf8XmlWriter#flush) and [Utf8XmlWriter.FlushAsync](/xmlessentials/api-reference/CloudNimble/Text/Xml/Utf8XmlWriter#flushasync); any other call throws an
[XmlException](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlException).

### <Icon icon="function" iconType="duotone" color="#419AC5" size={24} className="mr-2" /> WriteStringValueSegment

Writes a segment of text specified as a read-only span of UTF-8 bytes to the content of the current
element or to the value of the current attribute.

#### Syntax

```csharp
public void WriteStringValueSegment(System.ReadOnlySpan<byte> value, bool isFinalSegment)
```

#### Parameters

| Name | Type | Description |
|------|------|-------------|
| `value` | `System.ReadOnlySpan<byte>` | The UTF-8 encoded segment of the text to write. |
| `isFinalSegment` | `bool` | [`true`](https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/bool) to indicate that this is the final segment of the text; otherwise, [`false`](https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/bool). |

#### Exceptions

| Exception | Description |
|-----------|-------------|
| `XmlException` | The writer is not inside an element or an attribute.
-or-
The text is not valid UTF-8, or contains a character that XML does not allow.
-or-
A value of another kind is being written in segments. |
| `ObjectDisposedException` | This instance has been disposed. |

#### Examples

```csharp
writer.WriteStartElement("note");
writer.WriteStringValueSegment(firstBlock, isFinalSegment: false);
writer.WriteStringValueSegment(lastBlock, isFinalSegment: true);
writer.WriteEndElement();
```

#### Remarks

The segments together are written as [Utf8XmlWriter.WriteStringValue](/xmlessentials/api-reference/CloudNimble/Text/Xml/Utf8XmlWriter#writestringvalue) writes the whole
text. A segment can end in the middle of a multi-byte character: the writer keeps the bytes of the
incomplete character and writes it when the next segment completes it. After a segment that is not
final, the next call on the writer must be the next segment, apart from [Utf8XmlWriter.Flush](/xmlessentials/api-reference/CloudNimble/Text/Xml/Utf8XmlWriter#flush) and
[Utf8XmlWriter.FlushAsync](/xmlessentials/api-reference/CloudNimble/Text/Xml/Utf8XmlWriter#flushasync); any other call throws an [XmlException](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlException).
