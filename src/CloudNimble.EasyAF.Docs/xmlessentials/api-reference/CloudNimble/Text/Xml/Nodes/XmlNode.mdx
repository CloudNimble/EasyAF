## Summary

Defines the core behavior of a node in a mutable XML tree and provides a base for the classes that
represent elements, attributes, text, CDATA sections, comments, processing instructions, and the
XML declaration.

## Usage

`XmlNode` is the base class of every node in the mutable tree. It's the XML counterpart of `JsonNode`. You rarely create one directly: you create an `XmlElementNode` or one of the other derived types, or you call one of the static methods that parse XML into a tree.

- `Parse` reads a whole document from a `string` or from UTF-8 bytes and returns its root element.
- `ParseValue` reads the element a `Utf8XmlReader` is positioned on.
- `WriteTo` writes the node to a `Utf8XmlWriter`, and `ToString` returns its markup.
- `DeepClone` copies the node and everything inside it.
- `ValueKind`, `Parent`, and `NamespaceUri` are available on every node.

```csharp
const string xml = """
    <?xml version="1.0" encoding="utf-8"?>
    <!-- exported nightly -->
    <Order>
      <!-- rush -->
      <Item> Keyboard </Item>
      <Notes></Notes>
    </Order>
    """;

XmlNode order = XmlNode.Parse(xml);
output.WriteLine(order.ToString());

try
{
    XmlNode.Parse("<Order><Item>Keyboard</Order>");
}
catch (XmlException ex)
{
    output.WriteLine(ex.Message);
}
```

The code produces the following output:

```text
<Order>
  <!-- rush -->
  <Item> Keyboard </Item>
  <Notes></Notes>
</Order>
End tag does not match start tag.
```

The tree keeps the root element with its comments and indentation, and `<Notes></Notes>` keeps its end tag. The declaration and the comment before the root aren't part of it.

## Remarks

This class is the XML counterpart of `JsonNode` in System.Text.Json. Unlike
[XmlDocument](/xmlessentials/api-reference/CloudNimble/Text/Xml/XmlDocument), the tree can be changed, uses no pooled memory, and does not need to be disposed.
A tree that no thread is changing can be read from several threads at once. Changes are not
synchronized: while one thread changes a tree, no other thread can use it.

## Examples

### Parse one element from a reader

`ParseValue` leaves the reader on the end tag of the element it read, so the loop continues with the next one.

```csharp
ReadOnlySpan<byte> feed = """<Feed><Entry id="1"><Title>First post</Title></Entry><Entry id="2"><Title>Second post</Title></Entry></Feed>"""u8;

var reader = new Utf8XmlReader(feed);
while (reader.Read())
{
    if (reader.TokenType is XmlTokenType.StartElement && reader.LocalNameEquals("Entry"u8))
    {
        var entry = (XmlElementNode)XmlNode.ParseValue(ref reader);
        entry.SetAttribute("read", "true");
        output.WriteLine(entry.ToString());
    }
}
```

The code produces the following output:

```xml
<Entry id="1" read="true"><Title>First post</Title></Entry>
<Entry id="2" read="true"><Title>Second post</Title></Entry>
```

### Copy a node with DeepClone

```csharp
var order = (XmlElementNode)XmlNode.Parse("""<Order><Item sku="KB-1">Keyboard</Item></Order>""");
XmlElementNode item = order["Item"]!;
var backorder = new XmlElementNode("Backorder");

try
{
    backorder.Add(item);
}
catch (XmlException ex)
{
    output.WriteLine(ex.Message);
}

var copy = (XmlElementNode)item.DeepClone();
copy.SetAttribute("sku", "KB-1B");
backorder.Add(copy);

output.WriteLine(order.ToString());
output.WriteLine(backorder.ToString());
```

The code produces the following output:

```text
The node already has a parent.
<Order><Item sku="KB-1">Keyboard</Item></Order>
<Backorder><Item sku="KB-1B">Keyboard</Item></Backorder>
```

```csharp
output.WriteLine(new XmlCommentNode(" reviewed ").ToString());

{
    new XmlTextNode("Keyboard").ToString();
}
catch (XmlException ex)
{
    output.WriteLine($"Text: {ex.Message}");
}

{
    new XmlAttributeNode("id", "1042").ToString();
}
catch (XmlException ex)
{
    output.WriteLine($"Attribute: {ex.Message}");
}
```

The code produces the following output:

```text

<?print copies="2"?>
<?xml version="1.1" encoding="utf-8"?>

```

## Best Practices

- **Cast the result of `Parse` to `XmlElementNode`.** `Parse` and `ParseValue` return the base type, and the element members (`Children`, `Attributes`, the indexers) are on `XmlElementNode`.
- **Catch `XmlException` around `Parse` for input you don't control.** For a Boolean result instead, call `XmlDocument.TryParse` and then `CloneNode`.
- **Use a type pattern to tell nodes apart.** `child is XmlElementNode element` tests and casts in one step. `ValueKind` gives the same answer without the cast.
- **Parse through `XmlDocument` when you need options.** `XmlNode.Parse` takes none. `XmlDocument.Parse` with an `XmlDocumentOptions`, followed by `RootElement.CloneNode()`, gives you limits, a tree without white space, and stream input.
- **Read `Value` to inspect a text node or an attribute.** `ToString` throws for a node that can't stand alone as markup.

## Patterns

### Read, then edit

Use `XmlNode.Parse` when you intend to change the document, in one place or throughout: the tree makes nodes only for the elements you reach into. Use `XmlDocument.Parse` and `XmlElement.CloneNode` when you read the document with the typed getters of `XmlElement` and change a small part, or when you need `XmlDocumentOptions` or a `Stream`.

### Edit one record at a time

Read a large input with `Utf8XmlReader`, call `XmlNode.ParseValue` for each record you need to change, write the changed record with `WriteTo`, and move on. Only one record is in the tree at a time.

### Process nodes by type

```csharp
foreach (XmlNode child in order.Children)
{
    if (child is XmlElementNode { LocalName: "Item" } item)
    {
        output.WriteLine($"{item.Attributes["sku"]!.Value}: {item.InnerText}");
    }
}
```

This loop is part of the first example for the `CloudNimble.Text.Xml.Nodes` namespace. A property pattern picks the elements with one name and skips text, comments, and everything else.

## Considerations

- `Parse` returns the root element of the document. It doesn't return `null`; input with no root element throws an `XmlException`.
- `Parse` keeps comments and the white space between elements inside the root, and it records whether an element with no content was written as `<e/>` or `<e></e>` in `XmlElementNode.IsEmptyElement`. It drops the XML declaration and everything outside the root element.
- `Parse` takes a `string` or UTF-8 bytes and no options, so the default limits of `XmlDocumentOptions` apply (for example, a depth of 64) and the document size isn't limited. For a `Stream` or other options, parse with `XmlDocument` and call `XmlElement.CloneNode`.
- `Parse` and `ParseValue` keep the parsed input with the tree. An element makes its attributes and child nodes the first time you reach into it, for example through `Children`, `Attributes`, or `InnerText`, and an element nothing has reached into is written and copied from the parsed input. What the tree reads and writes doesn't depend on how much of it has been reached. The parsed input stays in memory while such an element is reachable, and it doesn't depend on your string, bytes, or reader after the call returns.
- `ParseValue` uses the options of the reader you pass. By default a reader reports comments and white-space-only text between elements, so the tree keeps both.
- `Parent` is `null` until the node is added to an element's `Children` or `Attributes`, and `null` again after it's removed.
- `NamespaceUri` is `null` on nodes that have no name (text, CDATA, comments, processing instructions, and the declaration). On an element or an attribute, it's an empty string when the name is in no namespace.
- `ToString` writes with a `Utf8XmlWriter` that omits the XML declaration, doesn't indent, writes every line end as a line feed on every operating system, and writes by the rules of XML 1.1, because a node doesn't know which version it was parsed from. A character that only XML 1.1 allows, or that XML 1.1 would normalize, is written as a character reference. It throws an `XmlException` when the node can't be written as it stands: a text node or an attribute on its own, an invalid name, or a prefix with no namespace.
- `WriteTo` and `ToString` are where the tree is validated. Building the tree checks only that a name or a processing instruction target isn't `null`, empty, or white space.
- `DeepClone` of an element that nothing has reached into shares the parsed input with the original, but the two are separate trees: a change to one doesn't show in the other.
